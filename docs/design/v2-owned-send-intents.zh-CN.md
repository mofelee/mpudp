# V2 发送意图所有权

[English](v2-owned-send-intents.md)

`Config.OwnedSends` 显式启用发送所有权，默认仍使用同步 `Config.Emit`。本次改动
不启用公共运行时工作线程，也不声称提高吞吐量。控制器不持有 goroutine、定时器或
socket。除工作线程执行意图的 `Release` 外，所有调用仍由所有者串行执行。

## 准入与所有权

此模式要求 `MaxInFlightSends` 为1..32、`MaxPathQueuedPackets` 为1..4096、
`MaxPathQueuedBytes` 不小于512且不超过账本上限，`MaxQueueResidence` 大于0且
不超过100ms。协商后的 DATA 包必须能放入路径字节上限，才能接收业务原包。

仅在有空闲工作线程时调用 `TakeSend(now)`。它接纳至多一个包；全局最多保留
`min(MaxInFlightSends, 协商 MaxPaths)` 个包，每条逻辑路径最多保留一个，由 DATA
与控制消息共用。路径上限大于1不会提高本次实现的路径并发。路径字节计入完整背板
容量，FEC 包使用精确大小背板；IP 头只计入发送节奏，不计入保留内存。

等待 FEC 描述符留在唯一密封组中，尚未分配路径，也没有包内存或路径槽位。路径
偏好仅在 `TakeSend` 时成为实际分配。组状态最多256项；等待控制消息保留在有界
控制帧中。组级等待描述符与已接纳路径包义务明确区分。

`SendIntent` 包含 token、类型、路径编号、已认证路由与绑定、固定发送器、包字节、
截止时间及原生时间能力。包与发送器只借用到 `Release`，必须先停止全部访问，包括
经由复制包装对象的访问。释放清空包字节与私有引用，可跨复制句柄幂等执行。控制器
独立持有私有所有者，重赋值公开包装对象不会改变已发 token 的所有权。

I/O 返回或调用前取消后，先释放意图，再可靠返回一个标量 `SendOutcome`。
`CompleteSend(now, outcome)` 要求意图已释放且 token 仍匹配。仅释放不会归还
全局/路径槽位或包字节义务。未知、重复、过期及不合法结果不会改变有效 token 表。
token 单调递增并检测耗尽。

`TakeSend` 出错时不返回意图；成功时可能同时返回新意图及 `Result` 中先前等待
工作的失败。适配器必须先登记意图，再处理结果。排队与分派不能满足 DATA 栅栏或
接收编码上下文 ACK 门禁。

## 观测与截止时间

`Invoked` 表示发送器调用已返回。原生 `AttemptKnown` 配合非零 `StartedAt`
表示连接 Write 前的时刻；零值加错误表示原生发送前检查拒绝。自定义调用显式
保留未知时间和普通 `Send` 的成功契约。调用前取消必须带错误且无开始时间。

控制器时钟只由所有者的 `now` 推进。工作线程时间必须在分派后，结束不晚于
`now`。原生尝试从 `StartedAt` 延长节奏，自定义未知时间调用保守使用
`FinishedAt`。序列化时间包含完整 UDP 包，以及 IPv4 的28字节或 IPv6 的48字节
头部。完成不能缩短已有节奏，也不能改变替换路由的节奏。

在构造引导路径或建立已认证加入状态时就固定原生绑定，而不是等到分派。socket
代数、地址元组及监听器源地址/OOB 保持固定。IPv4 映射地址按运行时绑定格式
规范化。Carrier 重建不能让旧意图转用新 socket。自定义发送器仍执行自身 `Send`，
并显式保留未知时间。

`ExpiresAt` 只限制调用前等待。适配器在开始 Send 前检查它；已执行 I/O 使用独立
超时，可以在该截止时间后结束。FEC 等待时间从组密封起计算，路径选择不重置。
控制帧队列时间与事务寿命分离。即使达到单步结果上限，过期工作也不会被分派。

Peer 工作线程全部忙碌时，`NextDeadlineWithSendCapacity(false)` 抑制分派就绪
与节奏时间，但保留队列过期、重试准备、控制寿命、密封及接收维护。仅剩已分派
工作时等待完成，不产生立即触发循环。`NextDeadline()` 保留普通就绪调度；旧同步
模式忽略容量参数。

## 完成、信用与关闭

组保留到全部分片按任意顺序终结。只有最后一个结果推进原包完成边界；部分消耗
原包跨组保留旧边界。首次失败保留粘性错误与失败起点。等待过期不调用发送器，
直接成为终结失败。

控制重试使用独立事务编号与帧版本。Join 阶段变化与上下文迁移保留寿命及尝试总数，
已分派尝试预占预算。晚到的实际尝试计入仍存在的事务，只有当前帧版本才能清除
分派状态、安排重试或打开 ACK 门禁。覆盖相同回复也产生新版本。发送前拒绝与
等待过期不计入实际尝试次数，但仍受重试间隔及原始寿命约束。

六个初始索引保持不变。`InitialOutput` 预付一个 FEC 输出。所有权模式下的
`InitialAssembly` 覆盖有界并行包，每个包保守保留本地完整包预算的两倍及意图
元数据。`InitialControl` 覆盖固定 token 与分片状态。按协商前本地提供上限预留，
安装只绑定而不重新申请。即使 Session 或 Peer 字节用尽，已接纳原包也能推进。

`BeginClose` 停止准入与分派，不阻塞，也不回收任何初始存储。未分派工作保持静止
直到最终清理。`Scope.Close` 后仍可处理受限完成，仅归还 token 义务，不推进栅栏
或创建工作。`FinalizeClose` 要求待完成 token 为0，再清空所有者并释放全部初始
租约。`Close` 调用两阶段，有活动发送时继续计费。延迟握手适配器必须等控制器、
工作线程、Carrier 及交付对象清理完成后，再调用存储释放续接。

[延迟握手清理](v2-deferred-disposal.zh-CN.md)。测试覆盖往返、信用饱和、部分原包、

节奏、控制迁移与覆盖、原生固定、回滚及 Scope 关闭后的清理。
