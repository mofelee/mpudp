## 已交付行为

现有初始 control lease 按本地 receive hard cap 预留一个串行包/record 工作区。
排队发送的数据不能在已准入组的完成片到达前耗尽该空间。其他组和原始报文目标仍
独立预留，固定工作区可能在相同总额度下更早拒绝发送准入。

真实双向回归先准入 32 组，再排入尚无法编码的 1400 字节发送报文；仅剩 568 字节
自由额度时，接收完成片仍可解码交付并释放额度，使发送继续。测试覆盖非对称 cap、
较大 bundle、预付构造失败、重入与 Close。完整产品 race/vet、106 项 Python 测试、
嵌套探针 race 及独立集成审查通过。

可选 `v2_receive` 区分累计 handler/资源/终止事件与当前 group/original/credit gauge。
累计计数在 Session 释放后保留，credit 包含整个 Peer 的发送与握手义务。
报告器验证存在的新字段并兼容旧记录，分别输出计数差值和结束 gauge。采样获取现有
owner mutex，不代表所有 socket/进程计数的同一瞬时原子快照。可选仪表导致 runner/
report 哈希变化，负载参数相同。[API](../API.zh-CN.md)定义详细语义。

## 实测饱和状态

下表事件差值来自对齐的 15 秒接收窗口，gauge 为结束快照，不是差值。
组完成表示 fragment 原子进入 original 重组，不一定产生业务交付。
Bundle 和拒绝计数表示 handler/准入尝试次数，包含重试。

| V2 方向/模式 | Bundle | 新组拒绝 | Original 拒绝 | 完成 / 过期组 | 结束待处理组 / original | 结束 credit 字节 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 上传 | 177543 | 168004 | 0 | 1817 / 1057 | 1057 / 0 | 16762866 |
| 上传聚合 | 176801 | 168906 | 6 | 1494 / 866 | 884 / 427 | 16769104 |
| 下载 | 182913 | 0 | 0 | 36582 / 0 | 1 / 0 | 156591 |
| 下载聚合 | 260082 | 0 | 0 | 52017 / 0 | 0 / 1 | 159205 |

包工作区拒绝始终为零，两项上传的结束快照都没有等待 original 准入的已解码组。
非聚合上传采样 0 至 7 一直保留 1057 个不完整组，每组预留 14850 字节，共
15696450 字节；计入其他义务后，在 16777216 字节上限下只剩 12302 字节，不足以
接纳新组。采样 0 至 7 的 82496 个 handler 尝试全部增加新组拒绝，完成组保持 4635。
采样 7 归还了 2048 字节，仍不够。采样 8 开始过期时，计入预热后距探针开始约
11 秒；交付短暂恢复，随后再度饱和。精确记录位于
`mpudp-p5-mpudp-upload-b1400-f1-diagoff-r1-v2/server-0.jsonl`：
采样 0、7、8 分别为第 4、11、12 行。

这直接证明该区间的不完整状态阻塞字节准入，但不能解释最初为何丢失足够多的 shard，
也不能把扩大上限或缩短超时视为性能修复。聚合还保留不完整 original；dispatcher
ingress drop 与主机负载仍需分析，二者都不等同内核 UDP 丢包。

## 独立 Profile

两项 profile 上传不属于六项吞吐表。接收 `Controller.NextDeadline` 在未聚合时占
累计 CPU 12.10 秒 / 47.41%，聚合时 11.80 秒 / 45.40%，自身占比分别为 45.69%
和 43.44%。这些累计值包含内部开销，不能相加。

之前的索引消除了待处理组/original 扫描，但路径循环仍存在。本源码第 548 和 553 行
遍历 listener 分配的 256 个路径状态并复制 reply/old-route 记录，在非聚合 profile
中占自身 CPU 10.10 秒。早期本地微基准仅使用五个路径状态，没有覆盖此 listener
容量；本客户端认证后的合同只允许五条路径。后续修复必须按该合同验证运行时容量
并重新测量。

CPU/mutex/block 在连接建立后开始采样，包含预热、稳态、本地 drain 和结果交换；
接收 CPU profile 时长分别为 19.21 和 20.97 秒。分配 profile 还包含更早启动分配，
heap in-use 是结束快照，不是稳态分配速率，也不是无 profile 对照的一部分。
