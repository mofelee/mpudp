## 修改与确定性证据

FEC 解码成功后，接收器丢弃原 shard 和重建工作区，但此前仍保留它们的额度，
同时原始报文的原子准入需要独立目标缓冲。新的 `Lease.ShrinkBytes` 仅归还已失效
的字节义务，继续计入完整逻辑 backing（包括 manifest）、描述符容量及活跃组元数据。
复制期间源和目标分别计费；完成的原始报文也归还已丢弃的范围表/链表额度，保留
交付 payload 及 lease 数量，包括零字节交付。

[认证回归测试](../../internal/sessionv2/credit_progress_test.go)通过真实路径准入
32 个 RS(3+2) 组，在解码时仅剩 1000 字节额度的条件下重建 1400 字节原始报文。
现在无需等待过期即可交付，其他 31 组的额度和原始期限不变。测试还覆盖 1/256
描述符、共享逻辑 backing、原子准入失败/重试、过期、同时存在的源/目标、空报文和
持有中的交付，以及 shrink/transfer/release/Close 竞争。完整产品 race、vet 和独立
审查通过。

这只归还已失效预留；真实的目标容量或 lease 数量不足仍会拒绝准入。解码前仍需
预留包处理工作区，内部其他所有权可能阻止完成包进入本次修复。远端记录缺少实时
接收额度 gauge，无法确定剩余内部状态；后续单独保护工作区并补充可观测性。

## 网络结果

基线是[上一轮截止时间对照](v2-deadlines-20260905.zh-CN.md)。两次运行都使用现有
五条每方向 100 Mbit/s 路径、20 ms 单向延迟、一个 Session 的单条业务流、RS(3+2)、
1200 字节 UDP 预算和 1400 字节原始报文，仅计每个原始报文的 1360 字节校验业务数据。
每项预热 3 秒、稳态 15 秒、运行一轮，关闭 profile/timing diagnostics，主机诊断为
basic。源码和 runner 工作树干净；网络测量期间暂停本地测试和微基准，未修改
VM/hypervisor 配置。

V2 上传仅 5/75 个预定 RTT 机会按时完成，聚合上传仅 1/75；空分位数不是低延迟。
聚合上传还有 20 次 echo 队列未接纳和 6 次 echo 写入失败。其他行均 75/75 按时回复。
未计入损坏或重复业务帧，全部本地尾部 drain 通过；本地 socket 尝试不能证明远端收到。

对齐的 15 秒接收采样中，上传 v1/v2/聚合的 dispatcher ingress drop 分别为
1,535 / 98,405 / 127,112，上一轮为 0 / 109,408 / 143,802。这是应用接收队列满时的

delivery-queue drop 均为零，不能认定剩余原因只有额度压力。两端 UDP 错误计数在
14 个完整内部采样区间内未增长；更宽的网络快照区间未发现数据接口 link/qdisc
drop 或 error 增长。

优化后各成本行均覆盖 15 个接收秒桶，最大边界偏差 238.91 ms，在 250 ms 容差内。
