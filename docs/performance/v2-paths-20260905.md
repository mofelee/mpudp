# V2 Negotiated Path Storage, 2026-09-05

[中文版](v2-paths-20260905.zh-CN.md)

Allocating controller path state only for the authenticated negotiated count
removes the observed upload stall in this short diagnostic. Nonaggregated v2
upload rises from 1.316 to 40.635 Mbit/s; aggregation rises from 2.085 to 92.689
Mbit/s. Receive admission rejections and expirations remain zero in the new
samples. The formal throughput and capacity requirements are still unmet.

## Runtime Change

The listener advertises up to 256 paths, while this client advertises five.
Previously `Controller.New` allocated the local maximum, so listener control and
deadline loops scanned 256 states although only five PathIDs could be used.
Construction now validates the exported contract count against the minimum of
the immutable endpoint profiles, checks that the bootstrap PathID is nonzero
and within that count, and allocates exactly that many states.

Bootstrap numbering, authenticated receive/Join bounds and complete local
carrier validation are preserved. Symmetric 256/256 negotiation still stores
256 states. Initial control credit remains sized for the full local offer,
because admission precedes peer selection; this change does not increase the
byte ceiling or remove the prepaid receive workspace.

## Same-Workload Comparison

The baseline is the [receive-state diagnostic](v2-receive-20260905.md). Both runs
use five 100 Mbit/s paths per direction, 20 ms one-way delay, one Session and one
flow, RS(3+2), a 1200-byte UDP budget and 1400-byte originals containing 1360
verified business bytes. Each case has three warmup seconds and 15 steady
seconds, one round, with profiles/timing diagnostics disabled and basic host
sampling. All workload parameters, topology and runner script hashes match.
Source and runner trees were recorded clean. Local tests and benchmarks were
paused during network measurement; no VM, router or hypervisor configuration
changes were made for this comparison.

These receiver event deltas use the aligned 15-second window; ending gauges are
snapshots. Completed groups have admitted fragments into original reassembly,
which need not immediately produce a business delivery. Bundles and rejection
counters count handler/admission attempts, including retries.

| Download | 276057 | 55212 | 0 / 0 / 0 | 0 | 1 / 0 | 170591 |
| Download aggregation | 292428 | 58484 | 0 / 0 / 0 | 0 | 1 / 1 | 161295 |

All sampled v2 endpoints, including warmup, retain zero cumulative rejection and
expiry counters and zero decoded-pending groups. Upload receiver observed
pending-group ranges are 0..2 without aggregation and 0..3 with aggregation;
observed credit ranges are 1066416..1196066 and 1066416..1412128 bytes. These are
sample extrema, not guaranteed high-water bounds. Credit covers the whole Peer
ledger, including other obligations, and is not process RSS.

In the baseline, the upload ending states were 1057 groups / 16762866 credit
bytes and 884 groups / 427 originals / 16769104 bytes, with 168004 / 168906
new-group rejection attempts. The new observations support removal of that
specific saturation episode; they do not prove immunity to other loss, load or
admission patterns. Every v2 sample and exact reporting boundary can be replayed
from the endpoint JSONL records in the diagnostic archive.

identity/command notes, identical fixture patch, production patch, two complete
fixture source files and their checksum index. The audit reconstructs the files

The fixture constructs real controllers through negotiated profiles and prepaid

with GOMAXPROCS 6, are not confidence intervals or transport throughput results.
The raw logs omit compiler version and executable hash; source attribution is
recorded by the producer and checked against the captured patches.
