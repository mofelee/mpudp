## 变更与推进保证

此前，已接纳的原始报文可能耗尽后续 FEC 输出或数据包组装预留所需的额度。
这些报文仍在排队时，重试不能释放所需额度。现在两个专用初始声明分别覆盖一个输出的
分片后备存储与所有者元数据，以及原有的两倍完整 UDP 数据包预算这一保守组装额度。
UDP1200 下，组装声明为 2400 字节。二者在发送间隙持续计费，原始报文接纳可用的
未承诺额度有所减少，但无法占用这部分推进保障。

安装时绑定已有声明，不再重新预留。大小按本地提议计算，协商后的更小数据包预算
仍在该额度内。输出工作区只允许一个存活分组，清除输出存储后归还槽位；工作区
Close 时若仍有存活输出，租约继续保留。独立聚合队列的 `Seal` 行为保持兼容。
控制器仍同步发送；本次没有增加工作线程、并发数据包、异步完成、节流策略或线格式变更。

[所有权设计](../design/v2-send-workspace.zh-CN.md) 说明了边界和测试。
Session 与 Peer 满额度回归覆盖已接纳原始报文的连续部分分组，并在发送期间由其他
接纳操作占用刚释放的载荷额度。另有回滚、更小协商预算、复制句柄及 Close 所有权测试。
这是路径和串行驱动仍可用时的本地内存推进保证；下述诊断没有刻意使账本饱和，
也不能证明任意故障下的远端交付。

## 分配成本

每项均为变更前 / 变更后。分配总量是所选边界间端点累计 `total_alloc_bytes` 的
精确差值；除以该端点实际时长得到 B/s，除以所选接收桶的验证业务字节得到
B/验证 B。启动阶段不计入。端点边界略有差异，因此这是窗口成本比率，不是逐字节
因果归因。下表 MB/s 为每秒十进制分配字节除以 1,000,000。结束堆大小和进程全生命周期
最大 RSS 是独立的瞬时值或高水位值。

## 压力与主机限制

接收端差值采用对齐的成本窗口，结束瞬时值是当前快照。bundle 数统计已认证的
处理尝试，包含重试；完成分组表示其片段已接纳至原始报文重组，不一定立即产生业务交付。

| V2 方向/配置 | Bundle 数 | 完成分组 | 新分组/原始报文/暂存拒绝 | 过期分组 | 结束分组/原始报文 | 结束额度字节 |

| 上传 v2 | 330635 | 66123 | 0 / 0 / 0 | 0 | 10 / 0 | 1231318 |
| 上传 v2 聚合 | 326092 | 65218 | 0 / 0 / 0 | 0 | 0 / 1 | 1089082 |
| 下载 v2 | 319431 | 63886 | 0 / 0 / 0 | 0 | 1 / 0 | 172993 |
| 下载 v2 聚合 | 295415 | 59083 | 0 / 0 / 0 | 0 | 0 / 0 | 158143 |

所有采样到的 v2 端点，包括预热阶段，拒绝/过期计数及已解码待处理分组均为零。
按表中顺序，接收端待处理分组采样最大值为 24 / 3 / 74 / 25。额度包含持续预留的
发送声明及全部其他 Peer 义务，不是 RSS 或分组级归因；采样最大值不是保证的高水位上界。

所有对齐窗口内的端点接纳反压、重试、等待、超时和取消计数均为零。基线聚合上传
记录了六个反压数据包和六次重试；本次未饱和的单轮测试不能证明接纳压力普遍不存在。

对齐的分发器入口、适配器及交付丢弃计数，套接字写入错误/超大包丢弃，以及端点主机
UDP 错误差值均为零。基线 v1 上传记录了 4683 次分发器丢弃，以及相互重叠的
UDP `InErrors=112`、`RcvbufErrors=112`。新运行的数据接口链路/qdisc 丢弃和错误
差值为零，管理接口丢弃保留在证据中。不同计数范围及端点边界不能建立精确的丢包恒等式。

虚拟化宿主机平均空闲仅为 8.18%..12.05%。宿主机在 v2 上传发生十页交换活动，
v2 下载为 512 页，聚合下载为一页；其他主机/场景交换计数为零。主机摘要采用
14 个完整内部区间，覆盖全部进程；网络快照从设置前跨越至排空后。这些限制使本轮
不能解释为隔离的网络容量测量。
