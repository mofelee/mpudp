# V2 方向认证状态，2026-09-05

[English](v2-authenticator-20260905.md)

预付额度的方向 HMAC 状态降低了四个 v2 用例中发送端和接收端每校验业务字节
的分配成本。吞吐仍有升有降：非聚合上传从 45.402 降至 44.430 Mbit/s，
其他 v2 用例提高。单次短时运行不能证明吞吐改善的因果关系、充足主机余量或
正式性能验收通过。

## 变更与范围

每个控制器分别拥有发送/接收认证器，由原有 owner 串行访问。FEC 编码使用
发送认证器，已建立会话的数据包认证使用接收认证器。每次操作重置带密钥哈希
状态并清空暂存数组。无状态 wire 函数继续使用局部状态，支持并发调用。
线格式、精确认证前缀/body 边界、常量时间 tag 比较，以及借用输入/调用方
拥有输出的规则不变。认证成功仍不代表获准接纳。

构造哈希之前，在初始 control 额度中增加两个各 4096 字节的专用预算，与
codec、接收暂存区独立计量。加上控制器两个指针，实测 amd64 版本的常驻预留
增加 8208 字节，Peer 字节上限不变。构造失败和 Close 都在释放已绑定 control
lease 前销毁新 owner。Close 清空自身密钥/暂存数组并移除哈希引用；标准
hash API 无法显式擦除不透明内部带密钥状态。

预算已按原生 Go 1.24/1.26 HMAC-SHA256（包括原生 FIPS 代码）存储结构审查，
不是 RSS 或其他 provider 的堆上限。保存的微基准使用原生 Go 1.26.4，不证明
BoringCrypto 的分配行为，也不是显式启用 FIPS 模式的计时运行。

## 分配成本

总量取各端选定遥测边界累计 `total_alloc_bytes` 的精确差值。除以该端实际
时长得到 B/s，除以所选接收桶的校验业务字节得到 B/校验 B；窗口前启动分配
不计入。两端边界略有差异，因此是窗口成本比率，不是逐字节因果归因。
结束 heap 和整个进程生命周期最高 RSS 是独立状态量。

每个表项均为优化前 / 优化后。比率保留六位小数；MB/s 为十进制分配字节每秒

所有 v2 端点样本（含预热）的拒绝/过期计数及 decoded-pending groups 为零。
接收待处理组样本最高值按表格顺序为 5 / 4 / 31 / 8。额度包括新增常驻 HMAC
预留和其他 Peer 所有权，不是进程 RSS 或单组归因。样本极值不保证高水位边界。

聚合上传记录六个发送背压数据报、六次接纳拒绝及六次重试，合计等待
4.543567 ms，没有超时/取消；其他发送端采样接纳计数为零。这与接收端接纳
拒绝计数是不同指标。

v1 上传记录 4683 次接收 dispatcher 入口丢弃，以及 server 主机 UDP
`InErrors=112`、`RcvbufErrors=112`；两项内核计数重叠，不能相加。
其他端点 UDP 错误增量及所有 v2 dispatcher 入口丢弃为零。基线曾有 560 次
v1 下载 dispatcher 丢弃。原始 socket 写错误/超大包丢弃、adapter/delivery
丢弃和发送端 dispatcher 丢弃均为零。数据接口 link/qdisc 丢弃/错误增量
为零，管理接口非零丢弃保留在证据中。不同计数范围及发送/接收边界不能建立
精确丢包恒等式。

Hypervisor 平均空闲仅 7.91%..11.62%。聚合上传 swap 七页，v1 下载六页，
v2 下载 178 页，聚合下载两页；其他主机/用例为零。主机汇总使用 14 个完整
内部间隔，覆盖主机全部进程；网络快照从设置阶段包围至排空结束。这些观测及
v1 上传丢包使本轮不能被视为独立网络容量测量。

## 独立原生微基准

基准归档保留 12 个原始文件、200 次观测：两个源码各 15 个无状态用例，
以及十个方向认证/构造用例，每项重复五次、每次 200 ms。测试与产品补丁已
按精确源码重建。基线只增加 envelope 认证基准，原有 FEC 基准不变；重构后
无状态与预热 owner 用例使用同一优化后测试可执行文件。

| UDP1200 操作 | 原始无状态 | 重构后无状态 | 预热方向 owner |
| --- | --- | --- | --- |
| Nil 目标编码 B/op，allocs/op | 1848, 9 | 1848, 9 | 1280, 1 |
| 认证 B/op，allocs/op | 544, 7 | 544, 7 | 0, 0 |
| 编码中位 ns/op | 5628 | 5201 | 4539 |
| 认证中位 ns/op | 5029 | 5110 | 3697 |

冷启动 owner 构造加 Close 单独记录 848 B/op、九次分配/op。所有形状的
无状态对象次数一致；字节数除最大 `reused_prefix_0` 外也一致：原始版本
三次 66105 B/op、两次 66104，重构版本五次 66104。保留所有观测、中位数
及范围。预热认证使用有效 FEC bundle body，无状态认证测试使用等长不透明
body。

独立复查了已捕获二进制哈希与只读构建元数据：Go 1.26.4、Linux/amd64、
CGO_ENABLED=1、GOAMD64=v1、GOEXPERIMENT 为空。记录的 GOMAXPROCS 环境
未设置，全部基准后缀显示运行时为六。二进制不含 VCS 源码证明，因此源码
关联和命令顺序仍为生产者记录，不是可复现构建证明。归档包含精确构建/运行
命令及哈希，不发布可执行文件。审计未重跑基准。短时本地计时不包含 owner
锁、传输、pacing 和完成流程，也不预测网络吞吐或跨 provider 分配行为。
