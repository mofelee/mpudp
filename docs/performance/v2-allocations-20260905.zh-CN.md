[English](v2-allocations-20260905.md)

## 运行时变更

`Controller.Completion` 返回发送完成进度标量。完成屏障在原有 owner 锁下读取
该值，避免通过 `Snapshot` 分配路径统计数据。取消、关闭、失败进度过滤和
完成通知保持原有行为。

目标缓冲区为 nil 时，`AppendFECBundle` 先校验完整 bundle，再分配最终数据包
缓冲区，直接在 envelope 前缀之后编码 body。非 nil 目标仍使用独立 body，
保证调用方输入别名安全。线格式、认证边界、调用方所有权及保守的两包额度预留
保持不变。不增加共享池、保留数据包缓存或额度上限。

## 分配计量

各端分配总量取选定遥测边界 `total_alloc_bytes` 的精确差值，不是用四舍五入
速率乘以 15。除以该端实际时间戳间隔得到 B/s；除以完整对齐接收桶中校验业务
字节之和得到 B/校验 B。发送与接收边界略有不同，因此这是窗口成本比率，
不能逐字节归因每次分配。选定窗口之前的启动分配不计入。结束 heap、进程整个
生命周期最高 RSS 及累计分配 profile 是不同指标。

## 独立微基准

基准归档保留三个日志共 180 次观测、精确源码补丁、测试文件，以及原始标量
校验和包。标量源码为 `302a07ed6f8d48010bc0a7114780db0f1c365ee1`；单缓冲区
源码为 `192153a909f48eb195d7b804b30aad5ac15d700d`。二者均基于优化前源码，
审计重建其在实测优化后源码中的集成。这是独立微基准，不是组合可执行文件的
测量。

Snapshot 与 Completion 在同一可执行文件中对照，Snapshot 实现未改。
五路径轮询从 1808 B/op、四对象/op 降为零。零 / 1057 个合成待处理组时，
Snapshot 中位 ns/op 为 1782 / 2007，Completion 为 1.710 / 1.868。
测试通过真实协商和预付额度构造控制器，待处理组仅为合成元数据；不包含 owner
锁、唤醒、取消、关闭及失败完成进度处理。

UDP1200、nil 目标编码从 3000 降至 1848 B/op，从十降至九次分配/op。
中位耗时为 5601 与 5625 ns/op，未证明 CPU 提速。非 nil 复用目标的分配
行为不变。覆盖 512、1200、最大包长及 1472 字节预算下十六条记录；最后一种
实际编码 1388 字节。优化后最大 nil 用例一次为 66105 B/op、四次为
66104 B/op；全部观测、中位数和范围均保留。

缓冲区基线只在优化前源码上增加两个相同测试文件，再应用编码器改动运行优化
版本。生产者记录命令及顺序，补丁匹配所指提交。日志记录 Linux/amd64、CPU
型号和并发后缀六，但没有捕获当时编译器版本或临时测试可执行文件哈希。
五次 200 ms 重复不是置信区间。审计没有重跑基准。

## 独立传输计时

计时归档包含同一优化后源码和二进制的两个额外上传用例，启用计时诊断、关闭
profile，排除在前后吞吐对照表之外。归档 reader 和精确 on/off JSON 已使用
固定版本报告脚本及审计后的公开输入独立复现；off JSON 也保留 v2 下载对照。

所有计时上传窗口选取接收桶 1..15。v2 / 聚合的 on 吞吐为 46.075 / 99.223
Mbit/s，略高于 off 不证明负的插桩开销或统计显著性。每条发送路径的 UDP
payload 为 1200 字节，约 4245 / 4157 PPS；payload 字节不含 IP/UDP 头。
分别记录发送/接收实际时长及边界偏差，不插值，也不按重叠窗口重新缩放。

下表单位为微秒，P99 为直方图桶边界。

| 上传配置 | 各路径 socket 写平均值范围 | Socket 写 P99 | 传输写队列平均值范围 | 写队列 P99 |
| --- | ---: | --- | ---: | --- |
| v2 | 17.870..22.612 | (64,128] 或 (128,256] | 0.102..0.118 | [0,1] |
| v2 聚合 | 17.074..20.905 | (64,128] 或 (128,256] | 0.104..0.114 | [0,1] |

SocketWrite 计量 socket 写调用墙钟时间（包含返回写错误），WriteQueue
只计量传输写互斥锁获取。二者都不计量 v2 owner 锁等待或 pacing 定时器迟到。
发送端 socket 写墙钟时间总和为 6.324 / 5.996 秒，传输队列总和为
0.03404 / 0.03412 秒。这不是 CPU 时间或实测 owner 锁占用比例。五条路径
平均值之和给出约 99.34 / 96.15 微秒的顺序写服务成本估计，不是实测组持续
时间分布，不能把各路径百分位相加得到组百分位。

配置的 `carrier-N` 和 `listener` 计数槽可以汇总多个 socket，并跨重建或
Session 变动保留；名称稳定不证明底层 socket generation 不变。listener
槽汇总 listener socket 写，不按远端路径拆分。每项发送
378 个反向/控制数据报；socket 写平均值为 63.901 / 68.096 微秒，P99
范围为 (512,1024]。选定窗口写错误为零。`analysis/timing-on.json` 保存
各路径精确包数、字节、速率、次数/总时长增量和全部 24 个非累积桶。各字段
独立采样，本次次数与桶总数一致不构成原子快照保证。生命周期 `max_ns` 无法
导出窗口最大值。关闭诊断的空直方图表示不可用，不是零延迟。传输写队列等待
较低不能排除 owner 锁竞争。
