## Network Comparison

Five independent 100 Mbit/s paths, 20 ms one-way delay, one flow, 1400-byte
messages and 1360 receiver-verified body bytes per message. MPUDP uses RS(3+2),
1200-byte UDP payload cap, 4096-entry queues and 8192 pending blocks. KCP uses
MTU 1400, window 1024, no KCP FEC, nodelay `(1,10,2,1)` and delayed ACKs.
KCP-over-MPUDP remains an experimental probe stack. Physical MTU is 1500;
offered load is unlimited. Each case has three seconds warmup and 15 seconds
steady load, one round. Both timing modes also collect CPU, heap, allocations,
mutex and block profiles, so timing off is still instrumented.

After-run host mean idle is 6.30%-8.77%, with a 4.04% minimum sampled idle.
Four case windows record one to three swap pages; the others record zero.
This shared-host, sequential single-round comparison cannot isolate causal
network speedup. Formal acceptance remains false; no new native-capacity or
KVM polling experiment is included.

All final completed-cache evictions, decoder-full, TooOldShards and pending
blocks/shards/bytes are zero. Receiver pending-block lifetime peaks are
111-348. Some cases still show ingress drops and expired groups; integrity
and delivery-drop counters remain zero. Timing-on sender retransmit deltas
are 29551 upload and 26566 download. KCP `LostSegs` denotes its RTO branch,
not proven network loss. The respective OutSegs-minus-adapter-segment deltas
are 247 and 1150 across separately sampled pipeline stages. Their causes and
exact pre-adapter drop counts remain unproven; original snapshots are retained.
