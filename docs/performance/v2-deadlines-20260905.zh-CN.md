## Profile 与实现

单独采集的基线 v2 聚合上传 profile 中，`sessionv2.Controller.NextDeadline`
占累计 CPU 13.84 秒、54.62%，自身占 8.56 秒、33.78%；其中原始报文截止时间查询
占累计 1.96 秒、7.73%。这些累计值相互包含，不能相加。dispatcher 每次等待前都
查询截止时间，不完整编码组积压后，重复扫描会与包处理争用 CPU。

两个接收组件都要求时间不倒退，并使用固定超时，因此准入顺序也是到期顺序。
侵入式链表支持最小截止时间查询与任意删除，过期处理只访问已到期项。
精确的已解码组计数可在没有待存储组时跳过重试扫描。完成、错误、过期和 Close
立即移除条目，不积累失效堆项。配置上限和截止时间不变；原始报文链表指针额外
计入 16 字节，编码组指针由已有结构大小计费覆盖。固定种子的扫描参照与所有权测试
覆盖相同时间、任意 ID/删除、事务回滚和精确到期边界。

本地微基准使用 Linux/amd64、Intel Xeon E3-1245 v5、200 ms benchtime 和真实待处理
条目；下表各操作均为零分配。Controller 数值为一次测量，原始报文数值为单 CPU
三次测量的中位数。基准证据目录保留原始测试代码、日志和命令。
本地优化后测量使用基线加未提交补丁，随后这些改动纳入修复，并非精确 `ed2d648`
版本的基准运行；下方优化后网络对照才使用该已提交版本。

| 操作，8192 个待处理项 | 优化前 | 优化后 |
| --- | ---: | ---: |
| Controller 下次截止时间 | 321.636 us | 568.5 ns |
| Controller 过期检查，无到期项 | 307.076 us | 46.06 ns |
| 原始报文下次截止时间 | 299.637 us | 41.07 ns |
| 原始报文过期检查，无到期项 | 366.115 us | 68.91 ns |

基线 profile 是独立诊断，不属于任一六项吞吐表。CPU、mutex、block 采样在连接建立后
开启，覆盖预热、稳态、本地 drain 和结果交换；`alloc_space` 还包括更早的启动分配，
heap in-use 是结束时快照，均不能作为稳态分配速率。本增量没有采集优化后的 CPU profile。

## 受控网络对照

两次运行均使用现有五条每方向 100 Mbit/s 路径、20 ms 单向 netem 延迟、一个 Session
中的单条业务流、RS(3+2)、1200 字节 UDP 预算和 1400 字节原始报文，仅计 1360 字节
校验后业务数据。每项预热 3 秒、稳态 15 秒、运行一轮，关闭 timing diagnostics 与
profile；源码和 runner 工作树干净。优化后网络测量期间暂停本地测试与微基准，未修改
VM 或 hypervisor 配置。[基线报告](v2-diagnostics-20260905.zh-CN.md)提供优化前完整数据。

CPU 按占用核心计量。近似 IPv4 比值对两端发送各计一次，每个 UDP 包加 28 字节，
包括未成功交付、校验片、填充和控制开销，不能确认物理限速器计费口径。
短时间顺序对照无法证明宿主余量，也不能将实现变化与运行间波动完全分离。
Hypervisor 平均 idle 为 7.51%-18.96%；下载 v1、v2、聚合测试还分别记录了 49、1、4
个 swap-page 变化。前后快照未发现数据接口 link error/drop 或 qdisc-drop 增长，
但不能排除单 socket 队列丢包。快照区间包含建立、预热和 drain，不是稳态计数差值。

## 剩余 Credit 压力

独立确定性复现证明，已失效的解码预留可能阻止原始报文准入。31 个不完整组和
一个已解码组占用 476216 字节额度中的 475216 字节，剩余 1000 字节不足以接纳
1400 字节原始报文及范围表/链表存储。没有外部持有的交付 lease；9998 次模拟
重试均无进展，直到较早组在 10 秒时过期才恢复交付。

本次 deadline 修改保留了此所有权行为。组预留仍包括已经丢弃的 shard 和重建工作区，
同时原始报文重组需要独立 backing。这与观察到的波形一致，但远端日志不包含精确
实时额度占用，不能证明远端处于同一状态。需要单独修复计费并重新测量。
>=250 Mbit/s 和 >=90% 容量目标、三轮 300 秒、原生 KCP、repair、mux 以及故障/MTU
验收均保持未完成。
